## Mid-flight: ultra code review

`main...HEAD` is too large for `/code-review ultra` (180+ files, 90k+
lines — mostly `cusum_validation/data`'s static reference datasets).
Split into two scoped reviews by constructing branches directly off
`main` containing `main`'s tree plus the target files' real content:

  `rtf_analyze.py`, `rtf_datacollator.py`, `grokfast.py`. 6,943 lines.
  **Already reviewed — 10 findings received, not yet triaged/verified
  against the real branch.** That triage is still outstanding.
- **`review-b-target`** (local branch, not pushed) — `realtabformer2.py`
  + its test + its full real dependency chain (same shared files as
  review-a, since v2 imports all of them). 7,472 lines. Rebuilt once
  already after discovering the first attempt was missing v2's actual
  dependencies (would have reviewed broken, non-importable code) —
  **not yet submitted to ultra.**

Neither branch is pushed (deliberate — they're throwaway scaffolding).
To rebuild either from scratch:

```bash
git worktree add -b <branch-name> <scratch-path> main
cd <scratch-path>
git checkout <HEAD-commit> -- <target files, including real dependencies>
git rm -f <any files that need to be absent, e.g. old data_utils.py>
git commit -m "..."
cd <repo-root>
git merge-base main <branch-name>   # must print main's own commit
git diff main...<branch-name> --stat   # sanity-check the size/scope
```

Then: `git checkout <branch-name>` and run `/code-review ultra main`
— **pass `main` as the argument, not the constructed branch.** Ultra
diffs via merge-base (three-dot semantics): the constructed branch
must be the target (current checkout), not the base argument, or the
merge-base collapses to the branch's own tip and the diff comes back
empty. (Found the hard way — first attempt had this backwards.)

**Before trusting any such review's findings**, verify the constructed
branch's target files actually `import` cleanly (`PYTHONPATH=src
python3 -c "import realtabformer.<module>"`) — a scoped branch that's
missing a real dependency will get reviewed as broken code, producing
misleading findings. This is exactly how the Python 3.9 `realtabformer2`
bug (above) was found — not through review, through this exact
sanity check.
